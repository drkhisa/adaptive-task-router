# Разработка и проверки

ATR — plugin с инструкциями, без исполняемых скриптов, внешнего MCP server и зависимостей. Основной файл — `skills/adaptive-task-router/SKILL.md`; справочники читаются только при необходимости.

## Устройство

Portable manifest находится в корневом `plugin.json`. Skills обнаруживаются в `skills/`, метаданные OpenAI находятся в `extensions.com.openai`. Каталог `.agents/plugins/marketplace.json` указывает на `./`, который разрешается от корня репозитория.

Устойчивые правила выбора отделены от меняющихся сведений о моделях, интерфейсах и уровнях размышлений. Информация runtime имеет приоритет над справочниками.

Сначала отбираются конфигурации с достаточным и ожидаемо сопоставимым качеством, затем сравнивается экономичность. Учитываются свойства задачи и результаты релевантных предыдущих попыток. Для выбора не запускаются все модели по очереди.

## Проверка изменений

Перед распространением:

- Проверьте manifest по канонической Agent Plugins 1.0.0 JSON Schema.
- Проверьте YAML metadata, одинаковые имена и явное `allow_implicit_invocation: true`.
- Проверьте относительные пути, ссылки, отсутствие секретов и персональных путей.
- Установите plugin через marketplace в изолированном профиле поддерживаемого клиента; проверьте обнаружение skill и справочников.
- Пройдите сценарии из `tests/routing-cases.md` в целевой среде, включая понижение, повышение, неизвестные настройки, контекст и проигнорированные советы.
- Проверьте остановку после предложения: задача не выполняется до ответа пользователя; сообщение о переключении возобновляет её, а любая ясная команда продолжить или обычное согласие выполняет на текущих настройках без повторного предложения и обязательной фразы. Простое совпадение настроек не вызывает паузу.

Проверяющие инструменты не входят в распространяемый plugin. Проверка структуры и согласованности сценариев не доказывает качество ответов всех моделей или гарантированное автоматическое включение. Поиск секретов по шаблонам не доказывает отсутствие всех возможных секретов.

В первичной проверке версии 0.1.0 проверены каноническая JSON Schema, metadata, пути и согласованность 56 сценариев. В изолированном профиле Codex CLI `0.154.0-alpha.6.2` успешно выполнены регистрация локального marketplace, установка, обнаружение skill со справочниками и удаление. Сравнительная оценка качества моделей отдельно не проводилась.

## Контекст, время и расход

После проигнорированного совета повторное непрошенное сообщение в той же задаче требует существенного изменения нужной конфигурации и достоверного интервала не менее 30 минут. Само время не запускает напоминание. Без временных меток интервал не угадывается. Явный запрос ATR или независимая новая задача допускает свежую оценку.

Состояние учитывается по видимому разговору, без отдельных файлов, таймеров и опроса часов. При исчезновении истории её нельзя выдумывать. Невозможность выполнить действие из-за отсутствующих инструментов объясняется в основном ответе, даже во время паузы.

Точная экономия токенов не измерена. Краткий входной файл, выборочное чтение справочников и подавление повторных сообщений сокращают накладные расходы, но загрузка инструкций всё равно расходует контекст.

## Обновления

Изменяйте продуктовые сведения, даты проверки, ссылки и затронутые сценарии вместе. Не обновляйте каталог веб-поиском на каждом пользовательском запросе. Фиксируйте изменения в `CHANGELOG.md`.

Рекомендация настроек не разрешает переключение, создание задач, делегирование, commits, push или deployment. Max — глубина размышлений; Ultra — отдельный режим с субагентами.

Работа идёт в локальной `dev`, стабильная версия устанавливается из `main`. Ветку `dev` нельзя отправлять на GitHub; публикуется только `main`. Мердж в `main` и push выполняются по команде владельца; публикация в каталоге OpenAI — отдельное действие.

## Область установки

Локальный Codex marketplace не доказывает облачную доступность plugin на всём аккаунте. Workspace admin может импортировать этот GitHub marketplace через Admin → Plugins; формат Agent Plugins 1.0 поддерживается этим импортом. Доступ ограничен выбранным workspace и его политиками. Использование в web/mobile нужно проверить после облачного импорта в новых разговорах.

Для любого личного аккаунта установка из GitHub с автоматической доступностью во всех клиентах не подтверждена документацией. Это незавершённое требование, которое нельзя считать выполненным по результату локальной установки. Пакет остаётся без локальных скриптов, hooks и MCP server; он готов к облачному распространению, но не выполняет его сам.

Источники: [Plugins and supported surfaces](https://learn.chatgpt.com/docs/plugins), [Workspace GitHub import](https://learn.chatgpt.com/docs/enterprise/plugin-management).

## Источники и выбор формата

Проверено: 2026-09-17.

- [Package your plugin](https://developers.openai.com/plugins/build/plugins): portable manifest, расширения OpenAI, установка и разрешение путей marketplace.
- [Build skills](https://learn.chatgpt.com/docs/build-skills): автоматическое и явное включение, metadata.
- [Models](https://learn.chatgpt.com/docs/models): модели, доступность и настройки интерфейсов.
- [Reasoning models](https://developers.openai.com/api/docs/guides/reasoning): поддерживаемые уровни reasoning.
- [Agent Plugins manifest schema](https://agent-plugins.org/schemas/1.0.0/plugin.schema.json): каноническая схема, использованная для проверки версии 0.1.0.

Встроенный plugin-creator создаёт поддерживаемый compatibility manifest `.codex-plugin/plugin.json`. ATR использует рекомендованный для новых portable packages корневой `plugin.json`.

Документация рекомендует desktop-установку и проверку. Текущий CLI также поддерживает `codex plugin add/remove`; README содержит desktop-вариант для клиентов без этих команд.
